Dokploy deployment guide

Install Cynone Builder on Dokploy

This guide shows how to deploy the Cynone Builder Go service as an external preview builder for Siteliyo. The service receives generated app files, runs the build, and returns the build output for preview.

Runtime

Go HTTP server plus Node.js/npm for workspace builds.

Port

Default service port is 8080.

Storage

Persist /app/storage for workspaces and logs.

Requirements

  • A Dokploy server with Docker enabled.
  • A domain or subdomain for the builder, for example builder.example.com.
  • The Cynone Builder folder from the package.
  • A strong secret value for WEBBY_KEY.
  • At least 2 CPU and 4 GB RAM. More is better for concurrent builds.
The builder runs npm install and npm run build inside generated workspaces. Do not deploy it on a very small server.

Prepare The Builder Files

Use the Cynone Builder directory as the deployment source. If you are deploying from Git, place these files in a repository: 

Builder/
  prebuilt/
    cynone-builder-linux
    prompts/
  Dockerfile
  docker-compose.yml

If you prefer building from Go source, use the src directory instead. The prebuilt binary path is simpler for Dokploy.

Create Dockerfile

Create a file named Dockerfile in the Builder directory: 

FROM node:22-bookworm

WORKDIR /app

COPY prebuilt/cynone-builder-linux /usr/local/bin/cynone-builder
COPY prebuilt/prompts ./prompts

RUN chmod +x /usr/local/bin/cynone-builder \
  && mkdir -p /app/storage/workspaces /app/storage/logs

EXPOSE 8080

CMD ["cynone-builder"]
Node.js is required because Cynone Builder runs npm commands while building preview workspaces.

Create docker-compose.yml

Create a file named docker-compose.yml beside the Dockerfile: 

services:
  cynone-builder:
    build:
      context: .
      dockerfile: Dockerfile
    environment:
      WEBBY_HOST: 0.0.0.0
      WEBBY_PORT: 8080
      WEBBY_KEY: ${WEBBY_KEY}
    ports:
      - "8080:8080"
    volumes:
      - webby_builder_storage:/app/storage
    restart: unless-stopped

volumes:
  webby_builder_storage:

Dokploy supports Docker Compose deployments and Docker named volumes. A named volume keeps generated workspaces and logs across redeploys.

Deploy In Dokploy

  1. Open Dokploy and create a new Docker Compose project.
  2. Connect the Git repository or upload/provide the Compose source.
  3. Set the compose file path to docker-compose.yml.
  4. Add an environment variable named WEBBY_KEY.
  5. Use a long random value for WEBBY_KEY.
  6. Deploy the service.
  7. Open the Dokploy logs and confirm the builder starts on port 8080.
WEBBY_KEY=replace-with-a-long-random-secret

Attach A Domain

  1. In Dokploy, open the Cynone Builder service.
  2. Add a domain such as builder.example.com.
  3. Point the DNS record to your Dokploy server.
  4. Enable HTTPS/SSL from Dokploy.
  5. Test the root URL in your browser.

The root endpoint should return a small JSON response with the builder version and session count.

Connect It To Siteliyo

  1. Open Siteliyo admin.
  2. Go to /admin/dashboard/preview.
  3. Select Cynone Builder as the preview runtime.
  4. Set Builder URL to your Dokploy domain, for example https://builder.example.com.
  5. Set Server key to the same value as WEBBY_KEY.
  6. Save the settings.
  7. Open a generated project preview and confirm the iframe builds through Cynone Builder.

Required API Endpoint

Siteliyo expects the builder to expose this endpoint: 

POST /api/import-workspace/:workspace_id

This endpoint imports the complete generated workspace before Siteliyo calls the existing Webby build endpoints: 

POST /api/build-workspace/:workspace_id
GET  /api/build-output-workspace/:workspace_id
If you use the patched Builder folder from this setup, the import endpoint is already added. If you deploy a clean Webby copy, add that endpoint first or previews will fail with an import-workspace error.

Quick Test

After deployment, test that the service is reachable: 

curl https://builder.example.com/

To test authenticated API access, send the key header: 

curl -H "X-Server-Key: your-secret-key" \
  https://builder.example.com/api/workspaces

Troubleshooting

Builder says key is required

Add WEBBY_KEY in Dokploy and redeploy.

npm command not found

Use the Dockerfile above. It is based on node:22-bookworm so npm and npx are available.

Builds are slow or fail randomly

Increase CPU and memory. Preview builds install dependencies and can use a lot of memory.

Previews disappear after redeploy

Make sure /app/storage is mounted as a persistent volume.

Siteliyo cannot connect

Confirm the Builder URL uses HTTPS, the domain points to Dokploy, and the Server key matches WEBBY_KEY.
